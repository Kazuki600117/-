# カスタマイズSEQ 5525（財務会計）：事業所別消費税計算方式対応

標準では財務コントロールマスタで全社1つしか設定できない消費税計算方式（積上方式／割戻方式）を事業所ごとに設定し、
消費税申告管理で出力区分＝事業所のときに、その事業所の計算方式で帳票・ファイルを出力する。

`standard/Win/MA_ShouhizeiSinkokusho` に改修前の M0000 標準ソースを置いている。

## 構成

| 種別 | オブジェクト | 内容 |
|---|---|---|
| テーブル | `M5525MS_MA_ZigyoushoSeigyo`（＋`History`、トリガ） | 事業所別制御マスタ。事業所ごとの消費税計算方式4区分と取引先コード |
| 画面 | `Obic7.3.0.Win.M5525.MasterM.MA_ZigyoushoSeigyo` | 事業所別制御マスタメンテ（新規） |
| 画面 | `Obic7.3.0.Win.M5525.Print.MA_ShouhizeiSinkokusho` | 消費税申告管理（標準を複製して改修） |

## 事業所別制御マスタ

| 列 | 内容 |
|---|---|
| `UriageZeiTumiageKBN` | R5.9.30以前売上消費税計算方式（0:割戻方式、1:積上方式。共通コード種別 40840。必須） |
| `SiireZeiTumiageKBN` | R5.9.30以前仕入消費税計算方式（同上） |
| `R5NenOctIgoUriageZeiTumiageKBN` | R5.10.1以後売上消費税計算方式（同上） |
| `R5NenOctIgoSiireZeiTumiageKBN` | R5.10.1以後仕入消費税計算方式（同上） |
| `TorihikisakiCD` | 取引先コード（varchar(10)）。取引先マスタ `P0000MS_Torihikisaki` に基準日時点の改定（`TorihikisakiKaiteiDate` ≦ 基準日）があることをチェック。次のカスタマイズで使用予定 |

列名は財務コントロールマスタ（`M0000MS_MA_Control`）と同じ。

## 消費税申告管理の動き

- 出力区分＝事業所：事業所別制御マスタの値で計算する。未登録の事業所は財務コントロールマスタの値
- 出力区分＝全社：標準どおり財務コントロールマスタの値
- 印刷（F7）・申告データ出力（F9）・XML出力（F10）のすべてに反映される
  （入力チェック `InputCheck` 内で計算方式区分を取得し直し、各帳票クラス・電子申告ストアドに引数で渡している）
- R5.10.1以後の売上＝割戻・仕入＝積上の組合せチェック（メッセージ 30444）も事業所の値で判定する

## カスタマイズSEQ

両画面とも DBアクセス・メッセージは標準と同じ SEQ 0000（`CUSTOMIZESEQ`／`CUSTOM_SEQ`）。

事業所別制御マスタメンテはシステム分類 M で次のメッセージを使用する。導入前に存在を確認する。

| メッセージCD2 | 用途 |
|---|---|
| 00104 | 未入力（消費税計算方式は必須） |
| 30423 / 30424 | 売上／仕入消費税計算方式が共通コードに存在しない（財務コントロールマスタメンテと同じ） |
| 00024 / 00026 | 事業所が存在しない／事業所名が未設定 |
| 00110 / 00111 / 00112 / 00113 | 閉じる・削除・登録・取消の確認 |
| 00100 / 00102 | 排他エラー（新規／修正・削除） |

## 導入手順

1. `Table/M5525MS_MA_ZigyoushoSeigyo.sql` を業務DBで実行
2. 2つの画面プロジェクトをソリューションに追加してビルドし、メニューに登録（消費税申告管理は標準と差し替え）
   - 事業所別制御マスタメンテの参照DLLは資産事業所マスタメンテと同じ構成（B0000/A0000）。HintPath はフォルダ構成に合わせて調整する

## 確認事項・制約

- 消費税計算方式の入力・検索・名称表示は財務コントロールマスタメンテ（`MA_CodeDialog`、`M0000MS_CommonCode` 種別 40840）と同じ作り
- 既にテーブルを作成済みの環境では、計算方式4列を NOT NULL に変更する（`ALTER TABLE ... ALTER COLUMN ... tinyint NOT NULL`、履歴テーブルも同様）

- 帳票クラス（`Obic7.3.0.Win.M0000.Report.MA_ShouhizeiSinkokusho`）と電子申告ストアドは、計算方式を引数で受け取る前提で改修していない。
  これらの内部で財務コントロールマスタを直接参照している箇所があれば、事業所の値が反映されないため、テストで確認する
- 取引先コードの検索は `Obic7fx.Win.P0000.Tool.Search.TorihikisakiCD`（参照 `Obic7.3.0.Win.P0000.Tool.Search`）。ダイアログの基準日（`BasicDate`）に画面の基準日をセットする
- 取引先名は基準日以前で最新の改定の `TorihikisakiName` を表示する。名称が NULL の取引先は廃止扱いとして入力エラー（表示ボタンで既存データを読み込んだときはエラーにせず表示のみ）

## テスト観点

- 事業所別制御マスタメンテ：新規・修正・削除、排他エラー、計算方式の必須チェック・共通コード検索（…ボタン・F4、種別40840）・存在しないコードのエラー（30423/30424）・名称表示、取引先コードの検索（…ボタン・F4）と存在チェック（基準日より後に改定された取引先はエラー）
- 消費税申告管理
  - 全社：標準（M0000）と出力結果が一致すること
  - 事業所（マスタ未登録）：標準の事業所出力と一致すること
  - 事業所（財務コントロールと異なる計算方式を登録）：積上／割戻の結果が切り替わること（算出基礎情報・付表・申告書・F9/F10 ファイル）
